Nebius × NVIDIA Global AI Hackathon / Agentic Engineering

A security agent that can prove it fixed your code.

Most AI code agents ask you to trust the diff. This one hands you a receipt. NVIDIA Nemotron writes the patch — then a deterministic verifier decides whether the patch is real: the finding's instance count must drop, no new finding may appear, and the target's tests must still pass. Anything else is rejected, and the failure goes to a stronger model.

02Why the verifier exists

The scanner says “cleared”. That is not the same as “safe”.

The first live run accepted four patches. Three were wrong — and the scanner accepted all of them, because it matches patterns, not intent. A verifier that reports “finding cleared, tests green” while handing back a broken tool is worse than no verifier at all: it manufactures confidence.

You are the verifier Four patches the model really produced on its first try. Accept or reject each one — then see what the deterministic audit said. Called correctly: 0 / 0
MCP005 shell execution — the model flipped the boolean SPECIMEN 1 / 4
@@ def run(cmd, limit: int = 1000) -> str: - subprocess.run(cmd, shell=True, check=False) - os.system(cmd) + subprocess.run(cmd, shell=False, check=False)
The rule is gone from the scanner's report. Do you accept the patch?
Rejected by the patch audit
shell=False on a single string. subprocess now looks for a file literally named after the whole command, so every command with arguments raises:

>>> subprocess.run('git status --short', shell=False)
FileNotFoundError: [Errno 2] No such file or directory: 'git status --short'

The scanner alone would have accepted this: shell=True is gone.
MCP006 SSRF — the model validated the URL's scheme SPECIMEN 2 / 4
@@ def fetch_and_save_remote_blob(target_url, output_path, payload): + if urllib.parse.urlsplit(target_url).scheme not in ("http", "https"): + raise ValueError("unsupported URL scheme") with urllib.request.urlopen(target_url) as resp:
A scheme check is a real validation. Do you accept it as an SSRF fix?
Rejected by the patch audit
No host allowlist. http://169.254.169.254/latest/meta-data/ has a valid scheme and a valid host — the check returns True for the cloud metadata endpoint that SSRF attacks are actually aimed at. A fix here needs an allowlist of hosts, not a test of syntax.
MCP007 Path traversal — the model confined by string prefix SPECIMEN 3 / 4
@@ def fetch_and_save_remote_blob(target_url, output_path, payload): + resolved = Path(output_path).resolve() + if not str(resolved).startswith(str(BASE_DIR)): + raise ValueError("path escapes the base directory") with open(output_path, "w", encoding="utf-8") as fh:
It resolves the path and checks the base directory. Accept?
Rejected by the patch audit
String prefix is not a boundary. '/app-evil/secret'.startswith('/app') is True, so a sibling directory that shares the prefix walks straight through. The remedy is os.path.commonpath or Path(resolved).is_relative_to(base) — a path-component test, not a text test.
MCP005 the same rule, fixed the canonical way SPECIMEN 4 / 4
@@ def run(cmd, limit: int = 1000) -> str: - subprocess.run(cmd, shell=True, check=False) - os.system(cmd) + subprocess.run(shlex.split(cmd), check=False)
Smaller diff than specimen 1, and it adds a function call. Accept?
Accepted — all three gates pass
Patch audit: no anti-pattern, and the remedy marker (shlex.split) is present. Rescan: MCP005 instances for run drop 2 → 0, and no new finding appears. Tests: unchanged. One patch, two sinks, both provably gone.

The fix: a third deterministic stage that reads only the lines a patch added

Never the existing file — so pre-existing code cannot trigger a rejection — and it rejects remedies that cannot work. It cannot hallucinate, it costs nothing, and it encodes the review a security engineer would do anyway. Rejection is fail-closed: a retry costs a fraction of a cent, a wrong patch costs trust in every other patch the tool produces.

src/vexar_autofix/verifier.py 
# Patterns look only at lines the patch ADDED, never the existing file.
SMELLS = {
    "MCP005": ((
        r"shell\s*=\s*False",
        "passing the command as one string; pass an argv list",
    ),),
    "MCP007": ((
        r"startswith\s*\(",
        "'<base>-evil' passes a check against '<base>'",
    ),),
}

# Absence is not proof of a bad patch, so markers are enforced only
# where the canonical remedy has a uniquely identifiable shape.
REMEDY_MARKERS = {
    "MCP006": (
        r"(ALLOWED_HOSTS|allowlist|hostname\s*(not\s+)?in\s)",
        "validating the scheme does not prevent SSRF",
    ),
}

Why not just ask a stronger model whether the patch is good?

Because that is the same failure one tier up: a model opinion, priced higher. This is a rule that returns the same verdict twice, runs in microseconds, and can be read and argued with by the person reviewing the diff.

Deleting the dangerous call is reported, not rejected

Sometimes deletion is right; sometimes it silently drops functionality. No mechanical check can tell which, so the report raises a review note and lets a human decide.

03How it works

A scanner on both sides of the model.

Five stages, three model tiers, one oracle. The scanner finds the sink, the models work on it, and the scanner is the thing that decides whether the work counted. It is the only participant the model cannot argue with.

The routing signal is the unusual part

Tiered demos usually route on request difficulty — a quantity nobody can measure before answering. This routes on verified failure: a signal that only exists because a deterministic checker is in the loop. The expensive model is never consulted on a guess, and it never has to work out what went wrong — the verifier tells it, in the words it will be graded against.

What gets auto-fixed — and what gets refused

Four rules have remedies mechanical enough to automate without judgement. Everything else is reported and left to a human.

MCP005shell execution on tool input
subprocess.run(cmd, shell=True) becomes subprocess.run(shlex.split(cmd), check=False)
The audit rejects shell=False on a single string: it silences the rule and breaks every call with arguments.
MCP006SSRF sink with no allowlist
urlopen(user_url) becomes host = urlsplit(url).hostname
if host not in ALLOWED_HOSTS: raise
The audit rejects scheme-only validation: the link-local metadata endpoint has a valid scheme and host.
MCP007path from tool input, unconfined
open(output_path, "w") becomes resolved = Path(output_path).resolve()
if not resolved.is_relative_to(BASE_DIR): raise
The audit rejects startswith and any base directory derived from the current working directory.
MCP010outbound HTTP without a timeout
urlopen(url) becomes urlopen(url, timeout=10)
An unbounded request is a denial-of-service waiting for a slow server; the fix is one keyword argument.
Property 1
Exact anchor edits
A patch either matches the source byte-for-byte or fails loudly. The model cannot silently reformat, reorder, or delete code it was not asked to touch.
Property 2
Working tree untouched
Every attempt runs against a throwaway copy in a temp directory. --apply is the only thing that writes, and only after verification.
Property 3
One finding per attempt
Each patch is small enough to review, a failure is attributable to one change, and partial progress survives an unsolvable rule.
04What it refuses

A confidently wrong fix is worse than a known finding.

Seven of the twelve findings in the vulnerable fixture are deliberately left alone. A tool description that is too short has no mechanical fix, and a model guessing at the author's intent produces a diff that looks plausible and is wrong. So the agent says so and moves on — and the report has a refused bucket so a skipped finding is never invisible.

RuleInstancesFateWhy it was left alone
MCP0011refusedBrief tool description — the remedy is wording, i.e. the author's intent.
MCP0032refusedMissing type annotations and an unconstrained Any parameter.
MCP0041refusedNo upper bound on a parameter — a schema decision, not a bug fix.
MCP0081refusedGeneric tool name — renaming changes the published tool contract.
MCP0152refusedUndocumented parameters; describing them is authorship, not repair.
7 refused instances · 4 security rules queued · 0 silently dropped

Every finding lands in exactly one bucket

Fixed, unfixed, refused, or skipped — the report accounts for all of them. An unaccounted finding is indistinguishable from a clean file, which would make the whole receipt meaningless.

The refusals are the honest part of the receipt

“Fixed 4 of 12” is a worse headline than “fixed 4, refused 7, hid nothing”. It is also the only version a security reviewer can act on.

Two bugs the receipts caught

Both were found by measuring, are pinned by a test, and both would have made a demo look great while being wrong.

Line-shifta perfect fix that read as six new findings
Findings were matched on (rule, tool, line). A patch that deleted two lines and added one renumbered everything below it, so a correct fix reported “1 cleared, 6 new findings appeared” and was rejected. Verification now compares rule-instance counts per tool, which survives reordering — and a targeted rule must actually drop.
Pinned by tests/test_verifier.py::test_line_shift_is_not_a_new_finding.
Self-comparereview notes that never surfaced
The review step compared the patched text with itself, because the variable had already been reassigned before the comparison. It silently reported nothing, forever. Fixed by capturing before_this_patch first; a deleted sink now produces a note a human sees next to the diff.
Both are the same lesson as the verifier itself: an output that is quiet is not evidence of correctness.
06Run it yourself

Everything on this page is four commands away.

The demo is static because a browser cannot hold an API key without exposing it — so instead of a button that lies about being live, every figure carries its timestamp and commit and can be regenerated locally.

bash 
$ git clone https://github.com/RANJITHROSAN17/vexar-autofix
$ cd vexar-autofix && pip install -e .
$ export NEBIUS_API_KEY=...        # tokenfactory.nebius.com
$ vexar-autofix --preflight          # key, endpoint, routed models
$ vexar-autofix --target examples/vulnerable_server.py
Python 3.10+ No key? --provider mock --rehearse-accept Dry run by default · --apply to write Eval python eval/run_eval.py

What you will see, unedited

Triage verdicts with reasons, every attempt with its verdict and the exact failure text, the fixed / refused / skipped buckets, and a diff. If verification never passed, the tool prints not fixed — target file untouched instead of a patch.
